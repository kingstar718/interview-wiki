# 论文写作专题

科目 论文 · 考频 ★★★★★ · 场景:论文写作→三、论文结构与模板,备考路线→四、八周里的论文安排

> **一句话**：论文不考文采，考「能不能把一次真实的架构决策讲清楚」。45 分及格线的关键在结构完整 + 理论展开 + 实践具体，素材提前备、每周动笔一次，比临场发挥稳得多。

## 一、评分标准与阅卷逻辑

- 45/75 及格；评分维度：论题相关理论正确性、实践真实性、结构完整、表达清晰
- 阅卷顺序：先看字数与结构 → 再看理论是否展开 → 最后看实践是否具体 → 是否跑题
- 实战经验：阅卷量大，**结构清晰 + 段落主题句 + 具体数字**最容易拿分；通篇空话最吃亏

---

## 二、选题与素材准备

- 近年题目归类：
  - 新技术：云原生数据库、Serverless、大模型（2025）
  - 数据架构：大数据 Lambda、湖仓一体、多模型数据库（2024-2025）
  - 工程实践：软件测试、负载均衡、事件驱动、单元测试（2024-2025）
  - 系统设计：秒杀场景（2025）
- 准备 2~3 个项目素材，每个素材四件套：**项目背景 / 技术选型 / 架构决策 / 质量属性验证（带数字）**
- 一个「云上业务系统」素材（含微服务 + 缓存 + 消息队列 + 云原生部署）可覆盖一半以上题目
- **系统建模题（UML/4+1 视图）**：素材里要有「建模组织」——类图/部署图/序列图怎么表达架构；论文里讲「如何用视图驱动设计」，而不是堆图

## 三、论文结构与模板

五段式结构（2500~3000 字）：

| 段落 | 篇幅 | 内容 |
|---|---|---|
| 项目背景 | 200~300 字 | 一句话业务 + 规模数据 + 你的角色与职责 |
| 相关理论 | 400~600 字 | 论题的概念、方法、标准；术语必须准确 |
| 实践应用 | 1200~1500 字 | 结合项目讲选型与决策，分 3~4 个要点，每点「论点 + 做法 + 效果」 |
| 问题与解决 | 200~300 字 | 一个真实遇到的坑 + 解决过程（明显的加分项） |
| 总结 | 200~300 字 | 收获 + 不足 + 改进方向 |

写作纪律：每段第一句就是论点；数字和对比（改造前后指标）比形容词有说服力；不写死模板句，防止阅卷看出套作。

## 四、八周里的论文安排

| 周次 | 做什么 |
|---|---|
| 第 1-4 周 | 读架构类文章时顺手攒素材：角色、选型理由、性能/可用性指标 |
| 第 5-6 周 | 每周 1 篇完整练习，120 分钟限时 |
| 第 7 周 | 3 篇成稿，按「结构/理论/数字」三项自评改稿 |
| 第 8 周 | 全真机考模拟 1 次；只复习素材，不背范文 |

---

## 五、机考写作要点与常见扣分点

- 机考：2500~3000 字，打字速度至少每分钟 35~40 字；善用系统字数统计；复制粘贴素材后必须改写
- 常见扣分点：
  - 跑题：只写技术不扣论题（比如论「性能测试」写成「系统设计」）
  - 套范文痕迹明显
  - 字数不足（2000 字以下基本无缘及格线）
  - 通篇理论、没有项目实践
  - 小标题混乱、段落无主题句
