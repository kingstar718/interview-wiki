# 刷题方案

> **一句话**：先用《代码随想录》的固定套路把模板刻进肌肉（每章只刷 2/3），再用 Hot100 做高频验收（Hard 只留 6 道），全程**只用一套思路**——这是投入最少、手撕最稳的路线。
>
> 本页讲**怎么刷**（顺序 / 刷哪些 / 跳哪些 / 刷几遍）；套路本身的原理见[算法总览](算法总览.md)，按套路查题见[算法题索引](算法题索引.md)，按热度查题见[高频题目索引](高频题目索引.md)。

**总量**：一阶段 94 题 + 二阶段 50 道新题（其中 43 题在一阶段刷过，直接进二刷）= **全程 144 题**，覆盖 Hot100 的 100/100。

## 一、这套方案的取舍

### 为什么先随想录，不直接冲 Hot100

Hot100 是**题目热度榜**，不是**教材**——它按"用户喜爱度"排序，同一道题网上有几十种解法，新手边刷边收集"奇技淫巧"，越刷越懵，考场上第一反应是"这题有个巧妙解法我想不起来了"，而不是"这题属于哪一类"。

随想录是**教材**：同类题统一固定解法，二叉树全用递归三部曲，回溯全用 `for + 递归 + 撤销`，背包全用两层循环。刷完你脑子里是**十来个能默写的模板**，不是一百个孤立的题目。

**顺序不能反**：先有模板，Hot100 才是"套模板的验收"；没有模板，Hot100 就是"一百道互不相干的难题"。

### 为什么每章只刷 2/3

面试手撕的取材范围比你想的窄得多：链表反转、二叉树遍历、双指针、滑动窗口、背包、DFS 灌水——反复考的就这些。随想录每章后半段的难题、偏题、冷门变种（欧拉路径、解数独、单调递增的数字、最小生成树……）**面试根本不出**，刷它们的时间拿去把前 2/3 二刷三刷，收益高一个数量级。

本页每章都标了「跳过」和跳过原因，照着跳就行，不用自己判断。

### 为什么不练思考、直接看答案

这个阶段的目标不是"练出思考能力"，是**快速建立模式识别**。硬啃一道没见过的 DP 题两小时，学到的是"这一道题"；看懂标准解法再默写一遍，学到的是"这一类题"。

思考能力是二刷之后自然长出来的——当你见过 90 道题的标准解法，第 91 道题的思路会自己冒出来。**一刷别硬啃，卡住 5 分钟就看答案。**

### 这套方案不适合谁

说清楚边界，免得走错路：

- **算法岗 / 竞赛 / 大厂 SP 加面**：考察深度远超 Hot100，本方案只是起点
- **Google/Meta 这类外企**：偏爱现场推导和 Follow-up 变形，"背模板"会被追问穿
- **只剩一周就面试**：直接从[高频题目索引](高频题目索引.md) Top 40 往下刷，本方案的一阶段来不及

对**国内大厂后端社招/校招的手撕环节**，这套方案够用且性价比最高。

## 二、第一阶段：筑基速通（94 题）

### 单题怎么刷（25 分钟一道）

| 步骤 | 时长 | 做什么 |
|---|---|---|
| 读题 | 3 min | 只确认输入输出和边界，**不想解法** |
| 看解 | 7 min | 直接看题解的「思路」+「代码」，看懂为止 |
| 默写 | 10 min | **关掉题解**，从零敲一遍，敲不出来就再看一眼再关 |
| 验证 | 3 min | 提交 / 手动跑一个例子；错了看「易错点」 |
| 收口 | 2 min | 用一句话写下"这题的标志特征 + 用哪个模板"，记在自己的错题本 |

**一刷的唯一验收标准是"能默写"，不是"能想出来"。** 想不出来很正常——你现在是在装弹药，不是在打仗。

**跳过 5 题**：93 复原 IP 地址（边界琐碎）、491 递增子序列（去重方式特殊，与 40/90 的套路不通用）、332 重新安排行程（欧拉路径，冷门）、[51 N 皇后](51-n-queens.md) 和 37 解数独（Hard，二阶段也跳）。

**本章模板**（只有一个，但要吃透三处变化）：
```
void backtracking(路径, 选择列表) {
    if (终止条件) { 收集结果; return; }
    for (选择 : 选择列表) {      // ← 变化 1:startIndex 控制"组合"还是"排列"
        if (剪枝条件) continue;  // ← 变化 2:used[] 或 i > start 控制去重
        做选择;
        backtracking(...);
        撤销选择;                // ← 变化 3:撤销一定要和"做选择"对称
    }
}
```
**组合用 `startIndex`、排列用 `used[]`、去重必须先排序**——这三句话记住，十道题都是它。

## 四、二刷与手撕自检

### 二刷的通过标准

一刷和二刷的验收标准完全不同，**别用一刷的标准糊弄自己**：

| | 一刷 | 二刷 |
|---|---|---|
| 允许看题解 | ✅ 直接看 | ❌ 完全不看 |
| 通过标准 | 能照着默写出来 | **60 秒内口述"哪个套路 + 模板骨架 + 复杂度"** |
| 单题耗时 | 25 分钟 | 5 分钟（说得出就过，说不出才动手写） |
| 做不出来 | 正常，再看一遍 | **记进错题本，三刷重点** |

二刷不是"再做一遍所有题"，是**快速筛出还没内化的题**。说得出的直接过，说不出的才值得花时间——通常 100 题里只有 20~30 题需要真正重做。

### 白板手撕自检清单

面试的手撕环境比 LeetCode 苛刻得多：没有 IDE、不能运行、没有测试用例、还要边写边讲。用这份清单模拟：

- [ ] **不开 IDE**：记事本 / 纸上写，没有语法高亮和自动补全
- [ ] **不能运行**：写完自己用一个例子在纸上走一遍
- [ ] **边写边讲**：写之前先口述思路，写完主动说时间/空间复杂度
- [ ] **主动问边界**：数组可能为空吗？有重复元素吗？数值范围会溢出吗？——**这一步是加分项，很多人直接开写就扣分了**
- [ ] **写完自己找 bug**：先检查边界（空输入、单元素、越界），再说"我觉得没问题了"
- [ ] **15 分钟内写完**：手撕通常只给 15~25 分钟，超时等于没做出来

### 错题本怎么记（一行就够）

不要抄题目、不要抄代码，只记**你当时卡在哪**：

```
LC 322 零钱兑换 | 完全背包 | 卡点:遍历顺序搞反了,求组合数要"先物品后容量"
LC 236 LCA     | 递归返回值 | 卡点:忘了"左右都非空说明当前就是 LCA"
```

三刷时只看错题本，不重刷全部。

## 常见追问

- **跳过的那些题以后要补吗？** 面试前不用。等你已经能稳定通过手撕环节，想再提升一层再回来补——那时候你会发现跳过的题大多是"已经会的套路换个皮"。真正值得回头的只有两类：Hard 白名单外但你面的公司特别爱考的（查[高频题目索引](高频题目索引.md)的公司标注），以及自己错题本里反复卡的。

- **只刷 2/3 会不会漏掉考点？** 会漏，但漏的是**低频考点**。本方案的 144 题覆盖了 Hot100 全部 100 道题、[高频题目索引](高频题目索引.md) Top 40 里的绝大多数。剩下的风险用另一种方式对冲更划算：与其多刷 50 道冷门题，不如把已刷的题二刷到"闭眼默写"——**面试挂在"见过但写不利索"上的人，远多于挂在"没见过"上的人**。

- **Hard 真的一道都不看吗？** 不是。本方案保留 6 道 ★★★★★ 的 Hard 必刷，另外 7 道要"读题解知套路"（各 5 分钟），只是不默写、不二刷。完全不碰 Hard 的风险在于：真遇到时连暴力解都说不出，直接冷场。

- **多久能刷完？** 4 周（每天 3~4 小时）或 8 周（每天 1.5~2 小时）。**别信"三天速通"**——模板的形成需要间隔重复，压缩到三天的结果是第四天全忘。

- **一刷就直接看答案，会不会养成依赖？** 一刷会，二刷不会。二刷的规则是**完全不看题解**，那一步会把依赖强行掰回来。真正危险的是相反的情况：一刷硬啃两小时不看答案，一周才刷 10 道题，最后因为进度焦虑而放弃。

- **用什么语言刷？** 面试用什么就用什么，本库题解是 Java。别为了"代码短"临时换 Python——手撕时面试官会追问语言细节（比如 Java 的 `HashMap` 扩容、`Integer` 缓存），用不熟的语言容易在追问里翻车。

- **刷题和背八股怎么分配时间？** 手撕通常只占面试 20~30 分钟、一到两道题，八股占的时间更长。但**手撕是硬门槛**——写不出来后面聊得再好也难过。建议：一阶段期间算法优先（每天 70% 时间），二阶段开始转成算法/八股各半，从[知识点索引](知识点索引.md)同步推进。
